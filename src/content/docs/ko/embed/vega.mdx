텍스트 파일로 스토리를 만들고 자신의 웹페이지에서 재생합니다. 먼저 대사 두 줄로 시작해서 배경, 소리, 모델을 더해 갑니다. 이 단계는 호스팅된 [Vega 브라우저 모듈](https://haneoka.org/embed/vega.js)을 쓰므로 npm 패키지를 설치하지 않아도 됩니다.

## 1. 여기서 플레이어 써 보기

**완전한 원본 예제**을 선택한 채로 **고른 내용 불러오기**, 이어서 **재생**를 누릅니다. 정원과 미라의 첫 대사가 보입니다. **다음 대사**으로 진행하고, **일시 정지**로 재생을 멈추며, 슬라이더로 스토리 안을 이동합니다. **플레이어 종료**는 플레이어를 닫으므로, 그 뒤 다른 스토리를 불러올 수 있습니다.

<DemoPlayer kind="story" locale="ko" />

원본 예제는 [이 완전한 story.json](/examples/story.json)과 [garden.svg](/examples/garden.svg)를 씁니다. **Our Notes: Treasure**는 모델과 사운드 리소스를 포함한 공개 게임 스토리를 불러옵니다. **고급 매개변수**의 설정은 다음 불러오기부터 적용됩니다. 언어 선택은 작성된 텍스트 중에서 고르는 것이며 단일 언어 스토리를 번역하지 않습니다.

## 2. 첫 스토리 저장하기

`my-story` 폴더를 만듭니다. 텍스트 에디터에 아래의 완전한 JSON을 붙여 넣고 그 폴더에 UTF-8로 **story.json**이라고 저장합니다. 파일 이름이 `story.json.txt`가 아니라 `story.json`인지 확인하세요. JSON은 데이터입니다. 따옴표와 쉼표는 그대로 두고, `const`나 `import` 같은 JavaScript 단어는 쓰지 마세요.

```json
{"localization":{"locales":["en"],"defaultLocale":"en"},"commands":[
  {"command":2,"targetName":"Mira","text":"This is my first story."},
  {"command":2,"targetName":"Mira","text":"Press Next line to continue."}
]}
```

[이 완전한 대화 JSON을 열어](/examples/dialogue.json) `story.json`으로 저장해도 됩니다. `commands`는 스토리 동작을 순서대로 나열한 목록입니다. 여기서 `2`는 Talk, `targetName`은 화자, `text`는 화면에 표시되는 대사입니다. 먼저 대사 두 줄을 편집하고 다른 필드는 그대로 두세요.

## 3. 웹페이지를 만들고 열기

[완전한 시작용 HTML을 열어](/examples/first-story.html) **index.html**로 `story.json` 옆에 저장합니다. [시작 폴더 전체 ZIP](/examples/first-story.zip)을 내려받아 압축을 풀어도 이 디렉터리를 얻을 수 있습니다. 복사할 수 있는 완전한 소스는 아래에 있습니다.

```text
my-story/
  index.html
  story.json
```

폴더를 HTTP로 제공합니다. Python이 없으면 [Python.org](https://www.python.org/downloads/)에서 설치하세요. Python 3이 있으면 `my-story`에서 터미널을 열고 다음을 실행합니다.

```sh
python3 -m http.server 8000
```

Windows에서는 `py -m http.server 8000`을 씁니다. 브라우저에서 [http://localhost:8000/](http://localhost:8000/)을 엽니다. 에디터의 로컬 HTTP 미리보기도 됩니다. 파일을 더블 클릭하면 `file://` 주소로 열리는데, JSON 요청에는 HTTP 주소가 필요합니다. 끝나면 Ctrl+C로 서버를 멈춥니다.

**Load / retry**를 누르고 **Loaded**를 기다린 뒤 **Play**를 누릅니다. 첫 대사가 나타나고, **Next line**으로 대사를 표시하거나 넘깁니다. 이 첫 스토리에는 이미지가 없어 배경이 단색입니다. 플레이어를 닫으면 리소스가 해제되며 다시 불러올 수 있습니다.

const button = id => document.getElementById(id);
const status = document.getElementById("status");
let handle, controller, generation = 0;

function controls(enabled) {
  for (const id of ["play", "pause", "next"]) button(id).disabled = !enabled;
}

  generation++; controller?.abort(); controls(false);
  const old = handle; handle = undefined;
  await old?.dispose();
}
button("load").onclick = async () => {
  button("load").disabled = true;
  let current;

    status.textContent = "Loading…";

      document: storyData,
      locale: storyData.localization?.defaultLocale ?? "en",

    await handle.ready;
    if (current !== generation) return;
    controls(true); status.textContent = "Loaded. Press Play, then Next line.";
  } catch (error) {
    if (current === generation) {
      const failed = handle; handle = undefined; await failed?.dispose().catch(() => {});
      if (current === generation) status.textContent = `Loading failed: ${error.message}. Check the file, then retry.`;
    }
  } finally { button("load").disabled = false; }
};
button("play").onclick = () => handle?.play();
button("pause").onclick = () => handle?.pause();
button("next").onclick = () => handle?.next();

</script>

스크립트는 세 가지 동작을 따로 수행합니다.

```js
const response = await fetch("./story.json"); // request the saved file
if (!response.ok) throw new Error(`HTTP ${response.status}`);
const storyData = await response.json(); // turn JSON text into a JavaScript object
const player = mountStory(document.getElementById("stage"), {
  document: storyData, // pass that object to the player
  locale: "en",
  assetsBase: new URL("./", response.url).href,
});
await player.ready; // the page enables Play only when loading succeeds
```

이 조각은 완전한 HTML의 불러오기 부분을 설명합니다. 파일 이름, URL, 파싱된 객체는 서로 다른 입력입니다.

| 가지고 있는 것 | 사용 방법 |
| --- | --- |
| JavaScript로 이미 만든 스토리 객체 | `mountStory(container, { document: storyData })` |
| 스토리 JSON 파일을 가리키는 HTTP 주소 | 위처럼 가져와 파싱하거나 6단계의 `httpDataSource`를 쓴다 |
| 파일 입력으로 고른 JSON 파일 | `fileDataSource`를 쓰고 이미지와 오디오를 가져올 곳을 고른다 |
| 공개 Haneoka 게임 스토리 ID | 7단계의 `haneokaStorySource`를 쓴다 |

## 4. 배경 더하기

[garden.svg](/examples/garden.svg)를 같은 곳에 저장합니다. `story.json`을 [배경이 있는 완전한 스토리](/examples/story.json)로 바꾸거나, 다음 동작을 `commands` 배열의 **맨 앞**, 첫 Talk 앞에 넣습니다.

```json
{"command":25,"background":{"url":"garden.svg"}}
```

`25`는 Stage입니다. `background.url`이 이미지 파일을 가리킵니다. 이 동작과 다음 Talk 사이의 쉼표를 유지하세요. 폴더에는 `index.html`, `story.json`, `garden.svg`가 있습니다. 플레이어를 다시 불러오면 대사 뒤에 정원이 나타납니다. 시작용 파일의 `assetsBase`가 이 폴더를 가리키므로 `garden.svg`는 `story.json` 옆에서 해석됩니다.

## 5. 소리 하나를 더하고 여러 큐 대응시키기

[cue-tone.wav](/examples/cue-tone.wav)를 `story.json` 옆에 저장하고 JSON을 [소리가 있는 완전한 스토리](/examples/story-sound.json)로 바꿉니다. 첫 대사와 함께 작은 원본 테스트 톤이 재생됩니다. 그 Talk 동작에 더해진 필드는 다음과 같습니다.

```json
"voices": [{"soundId":10000001,"categoryName":"Voice","playableUrl":"cue-tone.wav","volume":0.5}]
```

음성 대사를 쓰려면 WAV를 직접 녹음한 파일로 바꾸고 `playableUrl`을 그 정확한 파일 이름으로 변경합니다. `soundId`는 큐를 식별하고, `playableUrl`은 재생 가능한 오디오의 위치입니다. 브라우저가 소리를 허용하도록 **Play**는 클릭이나 탭으로 누르세요. SDK는 선언된 오디오를 공용 리소스 전송으로 읽고 재생 URL을 자동으로 준비합니다. 리소스 요청에는 설정한 바이트 예산과 기한이 적용되며, 해제하면 소유한 재생 URL이 풀립니다.

기존 스토리에 큐 ID가 있다면 주소를 JavaScript 맵 하나에 모으고 마운트 전에 음성 레코드를 채웁니다. 시작용 HTML에서는 `const storyData = await response.json();` 바로 뒤에 다음을 더합니다.

```js
const sounds = { 10000001: "./cue-tone.wav" };
for (const command of storyData.commands) {
  for (const voice of command.voices ?? []) {
    const key = voice.soundId ?? voice.id;
    if (Object.hasOwn(sounds, key)) voice.playableUrl = sounds[key];
  }
}
```

이는 샘플의 `commands[].voices`에 대한 호스트 측 준비이며, `sounds`는 `mountStory` 옵션이 아닙니다. BGM과 효과음 동작은 `bgm.playableUrl`과 `se.playableUrl` 레코드를 씁니다. 공개 Haneoka 스토리는 이미 사운드 레지스트리로 `voiceRefs`, `bgmRef`, `seRef`를 해석합니다. 다른 형식에는 타임라인이나 명령 그룹 안의 큐까지 포함해 큐 필드를 이 레코드로 바꾸는 어댑터가 필요합니다.

## 6. 다른 URL이나 선택한 파일 불러오기

[소스 선택이 있는 완전한 HTML](/examples/story-player.html)에는 네 가지 방법, 불러오기 오류 표시, 취소, 재생, 진행 슬라이더가 모두 들어 있습니다. 같은 JSON과 에셋 옆에 `index.html`로 저장합니다. **Another JSON address**를 고르고 주소를 붙여 넣은 뒤 Load를 누릅니다. 저장한 JSON을 고르려면 **A JSON file on my computer**를 선택합니다.

HTTP라면 더 짧은 SDK 경로로 시작용 파일의 fetch/JSON/mount 블록을 다음으로 바꿉니다.

```js
const { mountStory } = await import("https://haneoka.org/embed/vega.js");
const { httpDataSource } = await import("https://haneoka.org/embed/core.js");
handle = mountStory(document.getElementById("stage"), {
  source: httpDataSource({ url: new URL("./story.json", location.href).href }),
  locale: "en",
  signal,
});
await handle.ready;
```

`httpDataSource`는 JSON을 내부에서 가져와 파싱합니다. 상대 리소스 경로는 JSON 주소의 디렉터리를 기준으로 하고, 절대 URL은 자기 출처를 유지합니다. `assetsBase`는 리소스가 다른 디렉터리에 있을 때만 설정하세요.

JSON 파일을 선택하면 그 파일에만 접근할 수 있습니다. 옆의 이미지, 모델, 오디오 접근 권한은 주어지지 않습니다. 완전한 HTML은 `fileDataSource(file)`을 쓰고 그 리소스를 HTML 폴더에서 제공합니다. 모두 로컬에서 고른 리소스를 쓰려면 [로컬 파일과 fileResourceResolver](../core/#local-files)를 참고하세요. 모델 부속 파일 경로도 그 리소스 맵으로 해석되어야 합니다.

## 7. 공개된 Our Notes 스토리를 진입점 하나로 불러오기

Haneoka 스토리 ID가 있으면 `mountHaneokaStory`를 씁니다. 릴리스 매니페스트 하나에서 맞는 플레이어 모듈, 테마, Cubism 런타임을 고릅니다. 지정할 것은 스토리 ID, 서버, 언어입니다.

[완전한 단편 스토리 HTML을 열어](/examples/haneoka-story-en.html) `index.html`로 저장하고 3단계처럼 제공합니다. **Load**를 누르고 **Ready**를 기다린 뒤 **Play**를 누릅니다. 이 예제는 **afterlive_10109**를 씁니다. 작성된 명령과 에셋 참조는 [완전한 카탈로그 JSON](https://haneoka.org/api/v1/stories/afterlive_10109?server=intl)에서 볼 수 있습니다.

```js
import { mountHaneokaStory } from "https://haneoka.org/embed/vega-haneoka.js";
const player = mountHaneokaStory(document.getElementById("stage"), {
  id: "afterlive_10109", server: "intl", locale: "en",
});
await player.ready;
// Call from a button click:
player.play();
```

완전한 HTML은 요소, 버튼, 불러오기 단계, 취소, 오류 표시, 해제를 제공합니다. 네이티브 플레이어에는 장면 조작도 있습니다. 외부 버튼은 핸들 메서드를 보여 주는 것으로, 자신의 페이지에서는 레이아웃에 맞는 조작만 남길 수 있습니다.

페이지 안의 **Our Notes: Treasure** 프리셋은 더 긴 **millsage_004_1_02** 스토리를 씁니다. [완전한 공개 JSON](https://haneoka.org/api/v1/stories/millsage_004_1_02?server=intl)에는 명령 728개가 있습니다. 두 프리셋 모두 같은 짧은 API를 씁니다. `id`는 스토리 카탈로그가 반환하는 ID로 바꾸세요.

카탈로그 JSON에는 참조가 들어 있습니다. Haneoka 어댑터가 런타임, 모델 메타데이터, 미디어 레코드를 준비합니다. 직접 만든 완전한 Vega 스토리 JSON을 재생하려면 3~6단계의 `fetch → response.json() → mountStory({ document })` 경로를 유지하세요. Haneoka 도우미가 리소스 출처를 제공하므로, 리소스 기준은 고급 플레이어 옵션으로 에셋을 의도적으로 바꿀 때만 설정합니다.

## 8. 표준 Live2D 모델 준비하기

Cubism 제공자는 표준 `*.model3.json`과 구형 `*.model.json`을 받습니다. 표준 모델이라면 캐릭터 기술자가 매니페스트를 가리킬 수 있습니다.

```json
{"runtime":{"format":"cubism3","model":"models/Mira/Mira.model3.json"}}
```

내보낸 디렉터리 구조를 유지합니다.

```text
models/Mira/
  Mira.model3.json
  Mira.moc3
  Mira.2048/texture_00.png
  motions/...
  expressions/...
```

| 구성 요소 | 필요한 경우 |
| --- | --- |
| `model3.json`, 참조된 `.moc3`, 참조된 모든 텍스처 | 기본 모델 렌더링. 이름과 경로는 매니페스트와 일치해야 한다 |
| Cubism 플러그인, Web 런타임 모듈, 호환 Cubism Core | 모델 렌더링 실행. 기본 스토리 임베드는 모델 제공자를 자동으로 설치하지 않는다 |
| 물리, 포즈, 사용자 데이터 JSON | `FileReferences`에 선언된 경우. 안 쓰는 선언을 지우거나 참조된 파일을 제공한다 |
| 모션과 표정 파일 | 스토리가 쓰는 경우. 매니페스트 카탈로그와 파일 경로를 유지한다 |
| 추가 셰이더 JSON이나 셰이더 디렉터리 | 이 런타임에는 외부 셰이더 설정이 필요 없다. 렌더링 셰이더가 포함되어 있다 |

Live2D의 [내보낸 모델 파일 가이드](https://docs.live2d.com/ko/cubism-editor-manual/export-moc3-motion3-files/)와 [model3.json 사양](https://github.com/Live2D/CubismSpecs/blob/master/FileFormats/model3.json.md)을 참고하세요. 제공자는 매니페스트로 부속 파일을 찾습니다.

[완전한 모델 스토리 템플릿](/examples/story-model.json)을 `story.json`으로 저장합니다. `command: 0`은 시작 동작, `targets`는 미라 식별, `positionType: 5`는 중앙 배치, `characterModel`은 모델 지정입니다. `runtime.model`을 실제 매니페스트 경로로 설정하고 모델 부속 파일 이름과 디렉터리는 그대로 두세요. 6단계의 완전한 HTML을 쓰고 **Advanced: standard Live2D in my own story**를 펼쳐 Cubism 제공자를 켠 뒤, 원본 JSON을 고르고 Load, Play를 누릅니다. 이 템플릿에는 직접 내보낸 모델 파일이 필요하며, 내려받기에 그림의 모델 디렉터리는 들어 있지 않습니다.

**ZIP 입력은 현재 구현되어 있지 않습니다.** 모델 압축을 풀고 경로를 유지한 채 파일을 제공하며, 기술자가 그 매니페스트를 가리키게 하세요. 기존 모델 내보내기는 ZIP 다운로드를 만들 뿐 ZIP을 불러오지 않습니다. 공개 옵션에는 `shaders`나 `shadersDir`도 없습니다. 사용자 정의 셰이더 팩 로더에는 별도의 런타임 확장이 필요하며, 이 키를 스토리에 더해도 효과가 없습니다.

| 보이는 것 | 할 일 |
| --- | --- |
| `story.json: HTTP 404` | `http://localhost:8000/story.json`을 열어 파일 이름, 디렉터리, 대소문자를 확인한다 |
| JSON 파싱 오류 | 제공된 완전한 JSON을 쓰고 텍스트 값 하나만 편집한다. JSON은 큰따옴표를 쓰고 끝 쉼표가 없다 |
| `Failed to fetch` | JSON 주소를 직접 연다. HTTP 페이지를 쓰고 브라우저에서 실패한 요청 주소를 확인한다 |
| 다른 도메인의 CORS 오류 | 파일을 페이지 출처에서 제공하거나, 리소스 서버 응답이 페이지 출처를 허용하게 설정한다. 클라이언트 요청 헤더로는 CORS 권한을 얻을 수 없다 |
| 대화는 되는데 이미지·오디오 파일이 실패한다 | 문자 그대로의 경로와 `assetsBase`를 확인한다. JSON 하나를 골라도 부속 파일은 선택되지 않는다 |
| 모델 런타임이 실패한다 | 런타임 모듈, Core, 매니페스트, 바이너리, 텍스처 요청을 따로 확인한다. JSON을 가져왔다는 것은 스토리 파일을 읽을 수 있다는 뜻일 뿐이다 |
| 불러오기가 취소되거나 플레이어가 닫혔다 | `await player.dispose()` 뒤에 새 핸들로 다시 시도한다. 완전한 예제는 이를 대신 처리한다 |

## 재생, 정리, 고급 연동

`play()`는 시작이나 재개, `pause()`는 일시 정지, `next()`는 대사 진행입니다. `await player.seek(0.5)`는 선택지를 포함해 현재 도달 가능한 스토리 경로의 중간에 있는 명령 경계로 이동하고, 복원된 명령 인덱스를 반환합니다. `player.snapshot`은 상태와 진행도를 제공합니다. 상태 이벤트는 약 100 ms마다 갱신되고 조작 시에는 즉시 갱신됩니다.

`ready`는 렌더러, 필요한 리소스, 글꼴, 탐색 색인을 기다립니다. `cancel()`은 불러오기를 멈추고, 준비된 뒤 주어진 신호를 중단하면 플레이어를 해제합니다. `dispose()`는 멱등입니다. 같은 요소에 다른 플레이어를 마운트하기 전에 기다리세요. 리소스 실패는 `ready` 거부와 오류 이벤트로 나타나고, 관찰자 오류는 `onListenerError`로 격리됩니다.

런타임은 선언된 URL을 해석하고 대사, ID, 소스 라벨은 그대로 둡니다. 로컬 리소스 맵은 유니코드를 포함한 문자 그대로의 경로를 씁니다. 코어 로더는 소유한 Blob URL을 해제하고, 모델 제공자와 렌더러는 디코딩된 리소스와 GPU 리소스를 해제합니다. 전송 기본값은 CORS, 자격 증명 생략, 응답당 64 MiB, 리소스 기한 30초입니다. 동적 런타임 모듈과 Core 스크립트에는 자체 브라우저 로딩 경로가 있습니다.

모든 플레이어에는 [메인 사이트](https://haneoka.org/)로 연결되는 반투명 Haneoka 아이콘이 처음에 왼쪽 위에 표시됩니다. `brandingCorner: "top-right"`로 옮길 수 있습니다. 오버레이는 장면 영역 전체를 유지합니다. 스토리와 에셋의 저작권과 라이선스는 각자의 것입니다.

번들링 애플리케이션의 패키지 이름은 `@haneoka/embed-vega`이며, 테마와 Haneoka 도우미에도 패키지 하위 진입점이 있습니다. 공개 npm 설치는 아직입니다. 이 튜토리얼에서는 호스팅된 브라우저 모듈을 쓰세요. [소스 저장소](https://github.com/haneoka-gakuen/haneoka/tree/main/packages/embed-vega)에서 빌드할 때는 워크스페이스 의존성을 설치하고 빌드한 뒤 패킹합니다. 테마의 글꼴과 스프라이트 에셋은 빌드된 모듈과 함께 두세요. 연동 전체는 아래의 매개변수 참고에 있습니다.

자체 파일·네이티브 리소스 포트를 제공하는 Engine 연동은 [호스트 리소스](../host-resources/)에서 완전한 타입, 취소, 리스 소유를 참고하세요.

## mountHaneokaStory 옵션 전체

브라우저 진입점은 `https://haneoka.org/embed/vega-haneoka.js`이고, 번들용 패키지 하위 진입점은 `@haneoka/embed-vega/hosted`입니다. 호스팅된 진입점은 기본으로 자기 릴리스 매니페스트를 고릅니다. 패키지를 직접 가져오면 기본값은 `https://haneoka.org/embed/manifest.json`입니다. 컨테이너는 레이아웃 크기가 0이 아닌 브라우저 HTMLElement입니다. 브라우저 맥락이 없거나 ID가 비었거나 문자열이 아니면 TypeError, 해제 전 같은 컨테이너에 두 번째 호스팅 마운트를 하면 Error입니다. 핸들은 바로 반환되니 `ready`를 기다리는 동안 유지하세요.

| 옵션 | 타입; 필수/기본값 | 효과와 제약 |
| --- | --- | --- |
| id | 필수 문자열 | 현재 카탈로그가 반환하는 스토리 ID 그대로. 비었거나 공백이거나 문자열이 아니면 동기적으로 거부하고, 쓸 수 없는 ID는 소스 오류로 ready를 거부한다. |
| server | 선택 문자열; intl | 에셋 서버. 텍스트 언어와 독립. 기존 카탈로그 슬러그 검증과 제공 여부를 쓴다. |
| locale | 선택 문자열; ja | 시작 콘텐츠와 UI 언어. 공개 스토리 배열은 ja/en/zh-TW/zh-CN/ko를 쓴다. 스토리에 작성된 언어 중 하나를 고른다. |
| signal | 선택 AbortSignal | 시작을 취소한다. ready 뒤의 중단은 플레이어를 해제한다. 이미 중단된 신호는 ready를 거부한다. |
| manifestUrl | 선택 절대 HTTP(S) URL; 호스팅 ESM은 진입점의 릴리스 매니페스트, 패키지 가져오기는 안정 루트 | 호환 SDK 매니페스트를 고른다. 잘못된 URL·프로토콜은 예외, 잘못되거나 버전이 섞인 메타데이터는 ready를 거부한다. 완전한 릴리스 하나를 쓴다. |
| apiBase | 선택 절대 HTTP(S) 디렉터리; https://haneoka.org/api/v1/ | 호환되는 대체 스토리 카탈로그. 코어 디렉터리 검증을 쓴다. 모델 경로는 그 카탈로그에서 얻는다. |
| runtime | 선택 CubismEmbedOptions; 릴리스 런타임 기술자 | 고급 런타임 덮어쓰기. 필수 중첩 필드는 moduleUrl과 runtime.cubismCoreUrl, runtime.cubism2CoreUrl과 runtime.motionSyncCoreUrl은 선택. 라이선스를 받은 호환 모듈·Core URL을 쓴다. 팩토리 계약은 아래. |
| playerOptions | 선택 객체; {} | 조립된 플레이어에 넘기는 일부 mountStory 옵션. 전체 필드와 제외 항목은 아래. |
| fetcher | 선택 (Request)=&gt;Promise&lt;Response&gt;; 네이티브 fetch | 매니페스트, 런타임 기술자, 스토리, 리소스 전송. 기본 자사 요청은 no-referrer를 쓴다. 동적 모듈·Core 스크립트는 네이티브 브라우저 로딩을 유지한다. |
| headers | 선택 HeadersInit; 없음 | 코어 전송 헤더. 스크립트·모듈 요청은 네이티브 경로를 쓴다. |
| credentials | 선택 omit/same-origin/include; omit | 리소스 전송 자격 증명. 공개 읽기는 omit. 자격 증명이 있는 교차 출처 응답에는 서버 허가가 필요하다. |
| maxBytes | 선택 양의 안전한 정수; 67108864 | 시작과 하위 전송의 응답당 인코딩 바이트 제한. 잘못된 값은 RangeError, 초과하면 해당 읽기를 거부한다. GPU·디코딩 메모리 제한과 별개. |
| onEvent | 선택 (HaneokaStoryEvent)=&gt;void | 생성 시부터 stage, load, state, seek, error 이벤트를 받는다. |
| onListenerError | 선택 (unknown)=&gt;void | 관찰자 예외는 격리되어 여기로 전달된다. 리스너 실패는 재생 실패가 되지 않는다. |

`playerOptions`는 **theme, brandingCorner, shell, plugins, renderer, assetsBase, resolveResource, resourceTimeoutMs, resolveLocalizedText, onListenerError**를 받습니다. 중첩 필드, 기본값, 범위, 오류는 아래 mountStory 표와 같습니다. 이 도우미는 theme 기본값을 `haneoka`로 하고, 테마·Cubism 플러그인을 설치하며, 주어진 플러그인 배열을 뒤에 더합니다. 하위 플레이어는 shell을 명시하지 않으면 Haneoka 게임 셸을 씁니다. 평소에는 카탈로그의 리소스 기준을 유지하고, assetsBase/resolveResource는 리소스를 의도적으로 바꿀 때만 덮어쓰세요. 하위 옵션 검증은 시작 중에 수행되어 ready를 거부합니다. 최상위 onListenerError는 호스팅 관찰자를 다루고, playerOptions.onListenerError는 하위 계약을 따릅니다.

`playerOptions`는 **source, document, server, locale, signal, onEvent, fetcher, headers, credentials, maxBytes**를 제외합니다. 공유 맥락 필드는 최상위에 주세요. 이 자사 도우미는 카탈로그 ID를 받습니다. 작성 문서, HTTP JSON URL, 선택한 File에는 3~6단계의 mountStory와 소스 팩토리를 쓰세요.

| 핸들 멤버 | 타입·시그니처 | 동작 |
| --- | --- | --- |
| ready | Promise&lt;void&gt; | 고른 모듈, 런타임 기술자, 하위 데이터·모델·글꼴·탐색 준비를 기다린다. 원래 시작·불러오기 오류로 거부한다. |
| snapshot | StoryEmbedSnapshot | phase는 loading/ready/cancelled/error/disposed, playing/paused/finished/seeking, commandIndex/commandCount/progress. 래퍼 phase는 이 핸들을 나타낸다. |
| player | VegaPlayerHandle 또는 undefined | 고급 하위 접근. 수명은 호스팅 핸들이 소유한다. |
| stage | manifest/modules/runtime/data/resources/ready | 현재 준비 단계. 자체 불러오기 라벨에 쓸 수 있다. |
| release | 문자열 또는 undefined | 매니페스트를 읽은 뒤 고른 불변 SDK 릴리스. |
| play/pause/next | ()=&gt;void | ready가 필요하며 아니면 Error. 위임된 재생 오류는 하위 error 이벤트를 쓴다. |
| seek | (ratio:number)=&gt;Promise&lt;number&gt; | 유한한 0~1 명령 경로 진행도. 복원된 경계를 반환한다. 하위 범위·수명 주기 오류는 의미를 유지한다. |
| subscribe | (listener)=&gt;구독 해제 | 이후의 HaneokaStoryEvent를 받는다. 해제 후 구독은 Error. |
| cancel | ()=&gt;void | 불러오는 중인 시작을 끝낸다. ready 뒤에는 dispose를 쓴다. |
| dispose | ()=&gt;Promise&lt;void&gt; | 멱등. 취소하고, 시작 정리를 기다리고, 하위와 로더를 해제하고, 컨테이너 등록을 푼다. 정리 실패는 AggregateError로 거부될 수 있다. 재사용 전에 기다린다. |

stage 이벤트는 `{type:"stage",stage,release?}`입니다. load/state/seek/error 형태는 아래 mountStory와 같습니다. 공개 모듈 매니페스트와 런타임 기술자는 같은 릴리스에 속합니다. 잘못된 모듈 경로, 런타임 기술자 해시·길이 불일치, 배포 출처 밖의 런타임 경로, 가져오기 실패, 리소스 오류는 ready를 거부합니다. 시작이 실패하면 하위와 등록을 정리하므로 호스트가 새 핸들을 만들 수 있습니다. 자신의 수명 주기를 닫기 위해 실패한 핸들도 해제하세요.

## mountStory 옵션 전체

필수 위치 인수 `container`는 ownerDocument/defaultView가 있고 레이아웃 크기가 0이 아닌 브라우저 HTMLElement입니다. 브라우저가 아닌 컨테이너는 TypeError, 해제 전 같은 컨테이너에 두 번째 스토리를 마운트하면 Error입니다. 핸들을 동기로 반환합니다. TypeScript에서는 `document`나 `source` 중 정확히 하나를 고르세요. 구현은 주어진 source를 우선하며, 명령이 없거나 잘못되면 ready를 거부합니다.

| 옵션 | 타입; 필수/기본값 | 효과, 제약, 실패 |
| --- | --- | --- |
| document | AdvStory; source 대신 필수 | 메모리 엔진 문서. commands는 배열이어야 하며, 잘못된 문서는 TypeError로 ready를 거부한다. 작성 입력이며 5개 언어 카탈로그일 필요는 없다. |
| source | DataSource&lt;AdvStory&gt;; document 대신 필수 | `load(context)`가 엔진 문서를 반환한다. memory/http/file/사용자 정의 팩토리를 지원한다. 소스 실패는 ready를 거부한다. |

| renderer | ThreeRendererPluginOptions; \{\} | 렌더러와 포스트 텍스처 전체 설정은 아래. |

| signal | 선택 AbortSignal | 시작을 취소한다. ready 뒤의 중단은 이 플레이어를 해제한다. 리소스별 시간 제한은 별개. |

공통 로더 옵션 9개는 자세한 [코어 전송·리소스 계약](../core/)을 따릅니다. 마운트 자동 재생이나 전체 loadTimeoutMs 옵션은 없습니다. 전체 불러오기에는 외부 신호·기한을 쓰고, 재생은 사용자 동작에서 시작하세요.

사용자 정의 `postTextureResolver`에는 필수 `resolve(reference:unknown,usage)→Three.Texture|null`, 선택 `preload(requests,signal?)→Promise<void>`, 선택 `dispose()`가 있습니다. 각 요청은 `{reference,usage}`이고 usage에는 film-grain, color-lookup, lens-dirt가 포함됩니다. null을 반환하면 기존 파이프라인 대체를 허용합니다. 고른 Three 인스턴스와 호환되는 텍스처를 반환하고, 정리는 제공자가 맡습니다. 매개변수 충돌은 플러그인 생성 중 동기로 예외가 되고, 불러오기·렌더링·제공자 오류는 ready와 이벤트로 도착합니다.

## 소스, Cubism, 테마 팩토리

`haneokaStorySource({id,apiBase?})`에는 공개 스토리 ID가 필요합니다. apiBase 기본값은 `https://haneoka.org/api/v1/`이고 코어 디렉터리 검증을 따릅니다. 고른 스토리, story-runtime, 선언된 Live2D 메타데이터만 마운트의 server/locale로 불러옵니다. 스토리·모델이 없거나 카탈로그 레코드가 잘못되면 불러오기를 거부합니다. 릴리스나 계정 인수는 필요 없습니다.

`cubismStoryPlugin({moduleUrl,runtime})`에는 별도 라이선스를 받은 절대 모듈 URL과 `runtime.cubismCoreUrl`이 필요합니다. `runtime.cubism2CoreUrl?`과 `runtime.motionSyncCoreUrl?`은 선택적인 버전별 스크립트 URL입니다. 모듈은 createCubismWebRuntimeAdapter를 내보내야 하며, 내보내기나 제공자 기능이 없으면 모델 준비를 거부합니다. 이 플러그인은 모델이 필요할 때 어댑터를 지연 로드하고, 제공자 수명 주기를 유지하며, Core를 포함하지 않습니다. 호환되는 어댑터와 Core 버전을 함께 유지하세요.

`haneokaStoryPlugins`에는 옵션이 없으며 테마+기본 셸 플러그인 목록입니다. `createHaneokaThemeAssetsPlugin(provider)`는 선택 `assets()`, `resolveChatImage(value,kind:icon|stamp)`, `resolveSourceAsset(path)` 콜백을 받습니다. assets는 선택 URL 필드 arrow,auto,chatWindow,chatBackground,chatBackgroundFallback,chatLock,chatTextBox,chatComposerPlus,chatComposerPhoto,chatComposerPicture,chatComposerSmile,chatComposerMicrophone,chatIcons,fast,frame,fullscreen,subtitles,skip을 반환합니다. 덮어쓰지 않으면 기존 테마 에셋을 씁니다. HANEOKA_POST_TEXTURE_ASSETS는 고정된 허가 렌더러 에셋 맵이며, 필요하면 renderer.postTextureAssets로 주세요.

## 문서 형태와 핸들·이벤트 전체

AdvStory에는 commands(이 마운트에서 필수), 선택 runtime과 localization, 소스가 정의한 필드가 있습니다. localization에는 선택 locales:string[], defaultLocale:string, arrayOrder:string[]가 들어 있으며, 작성자가 정의하는 것으로 5개 언어 고정 요구가 아닙니다. runtime은 Vega의 Partial&lt;AdvRuntimeConfig&gt;이며 엔진을 통해 유지됩니다. 개별 명령 opcode와 리소스 구조는 고른 명령·제공자 스키마를 따릅니다. 예제는 공개 프로토콜의 Stage25와 Talk2를 씁니다.

| 핸들 멤버 | 시그니처 | 동작·오류 |
| --- | --- | --- |
| ready | Promise&lt;void&gt; | 렌더러·리소스·글꼴·탐색 색인 시작. onEvent가 error를 관찰해도 거부는 남는다. |
| snapshot | 읽기 전용 객체 | phase,playing,paused,finished,seeking,commandIndex,commandCount,progress. phase는 loading/ready/cancelled/error/disposed. |
| player | VegaPlayerHandle 또는 undefined | 준비된 고급 엔진 핸들: id,player,lifetime,root,slots,shell?,dispose(). 해제는 임베드에 맡긴다. |
| play / pause / next | ()=&gt;void | ready 필요(아니면 Error). Play는 재개한다. 비동기 인터프리터 실패는 error 이벤트가 된다. Next는 읽기 진행을 요청한다. |
| seek | (ratio:number)=&gt;Promise&lt;number&gt; | 유한한 0~1, 아니면 RangeError. 실제 명령 인덱스를 반환한다. 재생·일시 정지 의도를 유지한다. |
| subscribe | (listener)=&gt;구독 해제 | 이후 이벤트. 해제 후 구독은 Error. |
| cancel | ()=&gt;void | 불러오는 중인 시작만. ready 뒤에는 아무 동작도 하지 않는다. 다시 시도하기 전에 해제한다. |
| dispose | ()=&gt;Promise&lt;void&gt; | 공유·멱등 Promise. 로더·URL보다 먼저 엔진을 해제하고, 호스트 DOM·리스너를 없애고, 시작 정리를 기다린다. 정리 실패는 AggregateError. |

이벤트는 `{type:"load",event:EmbedEvent}`, `{type:"state",snapshot}`, `{type:"seek",commandIndex}`, `{type:"error",error}`입니다. load 이벤트 필드는 코어를 따릅니다. state는 바뀐 스냅샷을 100ms마다, 그리고 조작 시 공개합니다. 리스너 예외는 격리됩니다. 해제는 phase disposed로 끝나며, 그 state/load 이벤트는 생성 시 리스너가 관찰할 수 있습니다. 리소스·소스·플러그인 실패는 실제 오류를 유지하고, 취소는 signal.reason으로 거부합니다. 이 임베드는 두 번째 오류 코드 체계를 더하지 않습니다.

이 페이지는 안정 별칭을 씁니다. 이전 불변 r22 플레이어는 전용 줄 표기 레이아웃을 유지합니다. 리비전을 명시적으로 고정할 때는 엔진, 테마, 셸, 런타임 버전의 호환성을 유지하세요.
