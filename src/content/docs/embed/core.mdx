Load data and resource URLs for an embedded story, chart, or scene. The package provides a shared data layer for standalone hosts, browser applications, workers, and Node.js. It exports native ESM and TypeScript declarations. Importing it does not create elements, access `window` or `document`, start requests, or initialize a renderer.


## Release candidate installation

The examples use package imports resolved by your application. Official browser ESM is hosted at `https://haneoka.org/embed/core.js`. Package imports below describe a bundled application; npm publication remains a separate step.

## Installation

```sh
npm install @haneoka/embed-core
```

For the Haneoka public catalog adapter, also install its optional peer:

```sh
npm install @haneoka/api-client
```

The main entry has no runtime dependencies. `@haneoka/embed-core/haneoka` uses the public `@haneoka/api-client/haneoka` entry. Both packages use the browser Fetch API or the Fetch API provided by Node.js 20 and later. Serve browser modules through your bundler or an import map that resolves these package names to their ESM files.

## Read Haneoka's current data

```js
import { createEmbedLoader } from "@haneoka/embed-core";
import { haneokaDataSource } from "@haneoka/embed-core/haneoka";

const loader = createEmbedLoader({
  source: haneokaDataSource({ resource: "songs", id: "100070" }),
  server: "intl",
  locale: "en",
});

try {
  const song = await loader.load();
  console.log(song.musicTitle);
  // Use the resource URL supplied by the returned entity.
  const jacket = await loader.resourceUrl(song.jacketUrl);
  console.log(jacket);
} finally {
  await loader.dispose();
}
```

The adapter reads `/api/v1/{resource}/{id}?server={server}`. Omit `id` to read a collection index, or provide `view` to read an API collection view. The server chooses its current release for each data request; a release identifier and an account are unnecessary. Entity asset paths already identify their published resources. Use those paths as returned. Repeated `load()` calls request current data again.

`server` selects the data registry and defaults to `intl` for this adapter. `locale` defaults to `en` and is sent as `Accept-Language`; the API selects a supported response language. Catalog values retain their localized fields. The loader itself preserves your locale string and leaves text selection to the consuming host. Changing `locale` does not change the resource server.

For another Haneoka deployment, pass an absolute `apiBase`, such as `https://archive.example/api/v1/`. Relative asset paths resolve against that deployment's origin. `assetsBase` on the loader overrides this default when your resources live on another origin. The API adapter returns the entity or index payload, preserving the public client's validation and `ApiClientError` details.

## Load your own data and resources

Pass any authored data structure to `memoryDataSource`. A story host can accept its own story format, a chart host its chart format, and a scene host its scene format. The loader returns your data unchanged and by reference. Language fields and resource keys remain yours.

```js
import { createEmbedLoader, memoryDataSource } from "@haneoka/embed-core";

const authored = {
  language: "fr",
  title: "Une promenade",
  background: "背景/夕暮れ.png",
  lines: [{ speaker: "Alice", text: "Bonsoir !" }],
};

const loader = createEmbedLoader({
  source: memoryDataSource(authored),
  locale: authored.language,
  assetsBase: "https://cdn.example/projects/promenade/",
  resolveResource: (key) => key,
});

try {
  const data = await loader.load();
  const backgroundUrl = await loader.resourceUrl(data.background);
  // Pass data and the resource methods to your chosen story host.
  console.log(data.title, backgroundUrl);
} finally {
  await loader.dispose();
}
```

An HTTP JSON document uses the same consumer methods:

```js
import { createEmbedLoader, httpDataSource } from "@haneoka/embed-core";

const loader = createEmbedLoader({
  source: httpDataSource({
    url: "https://author.example/projects/promenade/story.json",
    decode(value) {
      if (!value || typeof value !== "object" || !Array.isArray(value.lines)) {
        throw new TypeError("Expected a story with lines");
      }
      return value;
    },
  }),
  locale: "fr",
});

try {
  const story = await loader.load();
  console.log(story.lines);
} finally {
  await loader.dispose();
}
```

The HTTP source resolves relative resources against the configured document URL's directory. A redirect does not change that directory. Provide `assetsBase` when your document describes another resource directory. `decode` validates or converts JSON for the actual consuming host; without it, HTTP and file sources return `unknown` in TypeScript. A generic type parameter describes your expected value, while a decoder performs runtime validation.

## Local files

`fileDataSource` accepts a browser `File`, a `Blob`, or a Blob constructed by a desktop host from bytes. A local JSON file has no implied network asset directory. Supply a resource map with the project's literal paths:

```js
import { createEmbedLoader, fileDataSource, fileResourceResolver } from "@haneoka/embed-core";

// Files obtained from your file picker or desktop host:
const createProjectLoader = (projectFile, backgroundFile) =>
  createEmbedLoader({
    source: fileDataSource(projectFile),
    locale: "fr",
    resolveResource: fileResourceResolver(new Map([["背景/夕暮れ.png", backgroundFile]])),
  });
```

Map lookup uses the exact Unicode key. `resourceBytes(key)` reads the Blob directly. `resourceUrl(key)` creates one URL per Blob and reuses it until disposal. Destroy the consuming media elements or renderer before disposing the loader; disposal revokes these URLs. URLs created by your own code remain your responsibility.

## Resource and transport options

`resourceUrl(key)` resolves a key and returns a usable URL. `resourceBytes(key)` resolves it and reads bytes with the loader's transport, cancellation, progress, and byte limit. An asynchronous `resolveResource(key, context)` can return a string, `URL`, or `Blob`. It receives the locale, optional server, signal, and configured fetcher. A resolver replaces the key mapping completely; missing local-map keys reject instead of falling through to the network.

Absolute URLs keep their origin. Relative strings use `assetsBase`; a leading `/` resolves from its origin root. `assetsBase` is an absolute HTTP(S) directory URL; the loader adds a trailing slash. Queries and fragments belong on resource URLs, rather than on the base. Supported resolved protocols are HTTP, HTTPS, Blob, and data URLs. Relative paths need an asset base even during SSR; the loader never guesses the current page's address.

```js
const loader = createEmbedLoader({
  source: memoryDataSource({ title: "Example" }),
  assetsBase: "https://cdn.example/project/",
  credentials: "omit",
  fetcher: (request) => fetch(request),
  maxBytes: 64 * 1024 * 1024,
});
```

`fetcher` receives a `Request` carrying `mode: 'cors'`, the cancellation signal, configured headers, and credentials. The default is native `fetch` with `credentials: 'omit'`. Choose `same-origin` or `include` for a service that requires cookies. Explicit headers are sent as configured; pass authentication headers only to the origins that should receive them. The fetcher also lets a desktop host implement its own transport.

Cross-origin API and resource servers must permit your application's origin through CORS. Cookie-based cross-origin requests require explicit origin and credentials permission from the server. Custom headers may require a preflight. A resolved URL later passed to an image, audio, or video element uses that element's own loading and CORS settings; it does not invoke this fetcher. See [MDN's credentials reference](https://developer.mozilla.org/en-US/docs/Web/API/Request/credentials) and [CORS guide](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS).

## Progress, errors, cancellation, and disposal

```js
const unsubscribe = loader.subscribe((event) => {
  if (event.type === "progress") {
    console.log(event.key, event.loaded, event.total);
  }
});
const controller = new AbortController();

try {
  const data = await loader.load({ signal: controller.signal });
  console.log(data);
} finally {
  unsubscribe();
  await loader.dispose();
}
```

Each load or resource call emits `start`, followed by byte `progress` events when bytes are read, then `ready`, `error`, or `cancelled`. `operation` identifies concurrent calls, and `key` is `$data` for the document or the resource key for resources. Progress measures decoded bytes for that operation. `total` is absent for unknown or encoded response lengths; memory loads and URL resolution do not emit byte progress. Connect these events to your host's loading indicator. `maxBytes` limits each JSON document or byte load and defaults to 64 MiB. A resolved URL alone does not download the resource.

HTTP sources reject non-success status with `EmbedHttpError`, exposing `status` and `url`. JSON parse failures, decoder failures, missing local files, byte-limit failures, and transport failures reject their operation. Haneoka API failures preserve `ApiClientError`. Listener failures go to optional `onListenerError` and do not change data operation results.

Abort a supplied controller to cancel that call, or call `loader.cancel()` to cancel all current calls. Cancellation rejects promptly even if a custom source ignores its signal; custom sources should use `context.signal` to stop their own work. Later calls remain available after `cancel()`. Concurrent calls are independent, with no automatic retries or shared data cache.

`dispose()` immediately prevents new calls, aborts current operations, revokes its Blob URLs, emits `disposed`, removes listeners, and invokes the source's optional cleanup once. Its shared promise resolves after cleanup; cleanup failures reject that promise. Call it after the consuming host has released its resource references. An owned custom source should be used by one loader when its cleanup releases resources.

## Custom data sources

Implement `DataSource<T>` when the data comes from another format or an existing application service:

```ts
import { createEmbedLoader, type DataSource } from "@haneoka/embed-core";

type Document = { title: string };
const source: DataSource<Document> = {
  async load(context) {
    context.signal.throwIfAborted();
    return { title: `A document in ${context.locale}` };
  },
};
const loader = createEmbedLoader({ source, locale: "pt-BR" });
```

Use the resulting data with the specific host's supported format. Resource methods supply URLs and bytes; playback controls, rendering, and GPU resource ownership belong to that host.

## All createEmbedLoader options

| Field | Type/required/default | Effect, combinations and errors |
| --- | --- | --- |
| `source` | required `DataSource<T>` | Must supply `load(context)`; loader calls it for each load. Optional source assetsBase supplies the resource directory, optional dispose runs once. Choose the source appropriate to the consuming host's format. |
| `server` | optional string; undefined | Passed unchanged to custom sources/resolvers. Haneoka adapter defaults it to intl and validates the registry slug through the public client. Language never chooses a server. |
| `locale` | optional string; en | Passed unchanged; author locales such as fr/pt-BR are valid. Haneoka sends it as Accept-Language for supported-language negotiation. |
| `assetsBase` | optional string; source.assetsBase, then none | Overrides source base. Absolute HTTP(S) directory, no query/fragment; trailing slash added. Invalid base throws TypeError at construction. Relative keys without a base fail URL construction. |
| `resolveResource` | optional `(key:string,context:DataContext)=>string\|URL\|Blob\|Promise<…>`; key unchanged | Completely maps a resource key. Result URL uses assetsBase when relative. Resolver rejection rejects that resource operation; missing local Map entry does not fall through to HTTP. |
| `fetcher` | optional `(Request)=>Promise<Response>`; fetch | Receives cors Request, caller headers, configured credentials and signal. Both document and resource reads use it. A downstream media element has its own transport. Throwing rejects the operation. |
| `credentials` | optional omit/same-origin/include; omit | Applies to loader transport. Credentialed cross-origin services must allow the embedding origin and credentials. Invalid values are rejected by native Request. |
| `headers` | optional HeadersInit; none | Shared transport headers; a source's per-request headers override matching names. Haneoka adapter sets Accept-Language from locale. Headers validation follows Fetch. |
| `maxBytes` | optional positive safe integer; 67108864 | Per decoded JSON/resource-byte response budget, not a total scene/cache/URL-resolution budget. Nonpositive/unsafe values throw RangeError at construction; oversized reads throw RangeError (Haneoka wraps response_too_large). |
| `onListenerError` | optional `(error:unknown)=>void`; ignored | Receives observer exceptions. Its own exception is isolated, and never changes the operation result. |

A loader has no constructor signal, timeout, decoder or automatic retry/cache option. Supply a per-operation signal, a source decoder, or a transport/source policy. Resolving a URL alone does not download bytes or apply maxBytes to the eventual media element.

## All source factories

| Factory | Required arguments | Optional arguments/defaults | Resource origin and validation |
| --- | --- | --- | --- |
| `memoryDataSource(data)` | any T, including an authored document | none | Returns the exact original value/reference; no default asset directory or cloning/validation. |
| `httpDataSource({url,decode?})` | absolute HTTP(S) string or URL | decode(unknown)→T; default parsed JSON | Factory validates protocol/URL. Base is configured URL's directory, not redirect destination. Loader maxBytes/signal apply; JSON parse/decode failures reject load. |
| `fileDataSource(file,decode?)` | browser File or Blob, including a host-created Blob | same decoder; default parsed JSON | No network base. Reads actual Blob bytes through loader budget/progress; invalid JSON/decoder rejects load. |
| `fileResourceResolver(files)` | ReadonlyMap&lt;string,Blob&gt; | none | Exact Unicode key lookup, no normalization. Missing key throws Error. URL calls create owned Blob URLs; byte calls read Blob directly. |
| `haneokaDataSource({resource,id?,view?,apiBase?,decode?})` | resource string | details below | Current public catalog adapter; no account or release parameter. |

Haneoka factory fields: `resource` is a manifest name with public-client resource syntax; `id?:string` selects an entity (omitted→index); `view?:string` selects a manifest projection; `apiBase?:string` defaults `https://haneoka.org/api/v1/` and must be an absolute HTTP(S) directory without query/fragment; `decode?` validates/converts the index/entity (default JSON value). Syntax/absent data errors follow [client](../../servers/client/) rules during load. Source asset base is the API origin root; a loader assetsBase explicitly overrides it. Server and locale belong to the loader context rather than this factory.

## Complete custom source and resolver context

A `DataSource<T>` declares `load(context): T|Promise<T>`, optional `assetsBase?:string`, and optional `dispose():void|Promise<void>`. The loader invokes cleanup once during disposal and waits for it; cleanup rejection rejects the shared disposal promise. Use a fresh owned source when its cleanup releases resources used by another loader.

`DataContext` contains these six public fields:

| Field | Type | Meaning |
| --- | --- | --- |
| server | optional string | Configured source registry, unchanged. |
| locale | string | Configured/default author language. |
| signal | AbortSignal | That operation's cancellation signal; use it in your work. |
| fetcher | (Request)→Promise&lt;Response&gt; | Loader's configured transport. |
| maxBytes | number | Effective decoded-byte budget; custom parsing should honor it. |
| progress | (\{loaded:number,total?:number\})→void | Reports actual operation bytes; omit total when unknown. |

`progress`'s argument has its own `loaded`/optional `total` fields. The resolver returns a string, URL or Blob synchronously/asynchronously. Absolute HTTP/HTTPS/Blob/data URLs keep their origin; relative strings use the effective assetsBase and `/` starts at its origin root. Other protocols throw TypeError. The loader never invents a browser/SSR page base.

```ts
const source = {
  assetsBase: "https://author.example/project/",
  async load(context) {
    context.signal.throwIfAborted();
    const response = await context.fetcher(new Request("https://author.example/project/story.json", { signal: context.signal }));
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    return response.json(); // use your format-specific bounded decoder here
  },
  dispose() { /* release resources owned by this source */ },
};
const loader = createEmbedLoader({ source, locale: "pt-BR", resolveResource: key => key });
```

## Every handle method and property

| Member | Arguments/defaults and result | Lifetime behavior |
| --- | --- | --- |
| `locale` | readonly string | Effective locale. |
| `server` | readonly string or undefined | Explicit server, before an adapter applies its fallback. |
| `disposed` | readonly boolean | Becomes true immediately when dispose starts. |
| `load(options={})` | optional `{signal?:AbortSignal}`; Promise&lt;T&gt; | New independent source operation, key $data; repeated loads call source again. |
| `resourceUrl(key,options={})` | required string + optional signal; Promise&lt;string&gt; | Resolves key, no byte fetch. One cached URL per owned Blob until dispose. |
| `resourceBytes(key,options={})` | required string + optional signal; Promise&lt;Uint8Array&gt; | Resolves key and reads bytes with status/budget/progress. |
| `subscribe(listener)` | required `(event:EmbedEvent)=>void`; returns unsubscribe function | Receives future events; does not replay state. Throws if already disposed. |
| `cancel()` | no arguments; void | Aborts all current operations; leaves loader reusable. |
| `dispose()` | no arguments; shared Promise&lt;void&gt; | Immediately disallows work, aborts active calls, revokes owned URLs, emits disposed, clears observers and invokes source cleanup once. Idempotent; disposed loader cannot be reused. |

Per-call signal cancellation rejects promptly, including when a custom source ignores its signal. The loader suppresses late ready/progress. Source work should still observe context.signal to stop its underlying activity. `cancel()` preserves later calls; `dispose()` ends the loader. Release consumers before revoking URLs; URLs authored by your own code remain your responsibility.

## Complete events and failures

| Event type | Fields | When |
| --- | --- | --- |
| start / ready | operation:number, key:string | Begin / successfully finish an operation. |
| progress | operation,key,loaded:number,total?:number | Bytes actually read. Memory data/URL-only resolution have no automatic byte progress. Compression/unknown Content-Length omit total. |
| error / cancelled | operation,key,error:unknown | Failure / cancellation. |
| disposed | type only | Loader disposal; cancellation failures are suppressed after disposal. |

IDs increase independently per loader; key is $data or the literal resource key. Listener errors do not reject operations. Concurrent operations are independent; there is no data-level deduplication or retry. The small demo retains at most32 displayed records while the SDK's event stream remains unchanged.

`EmbedHttpError(status,url)` extends Error with name/message/status/url for a non-success HTTP/resource read. Invalid URLs/bases/resolved protocols throw TypeError, exceeded byte budgets throw RangeError, invalid JSON throws SyntaxError, and authored decoder/source/resolver errors remain theirs. Haneoka API failures retain ApiClientError; its response budget reports code response_too_large, HTTP status and nonretryable default. Abort rejects with the signal reason, usually AbortError/TimeoutError. Calls after dispose reject Error; source cleanup failure rejects dispose.

## Optional branding helper

`createHaneokaBranding(document,options={})` is exported by the hosted core facade and the package `/branding` entry. Required `document` is the host DOM Document; `corner?:"top-left"|"top-right"|"bottom-left"|"bottom-right"` defaults top-left. It returns an HTMLAnchorElement, makes no image request, and does not append itself. Append it as a translucent overlay to a positioned full-size host, preserving its48px touch target, and remove it during cleanup. The href is fixed https://haneoka.org/, target _blank with noopener; original inline SVG/48px touch target/focus are supplied. Visual embed hosts manage this helper automatically. Importing data-only core creates no DOM.
